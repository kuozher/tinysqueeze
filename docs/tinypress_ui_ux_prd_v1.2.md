# [PRD v1.2] 輕量級圖片壓縮與轉檔桌面工具 (UI/UX 規格與微互動設計系統)

## 1. 產品定位與設計原則

* **核心定位**：專注於極致輕量、零心智負擔、批次多執行緒且產出品質對標 TinyPNG/MozJPEG 的原生級桌面工具。
* **設計原則（Anti-AI Slop）**：
  * **工具本位（Tool-First）**：排版服務於「效率確認感」，摒棄所有無意義的裝飾性漸層、背景光暈或隨意擺放的星芒圖示。
  * **克制矩形語彙**：按鈕全面採用微圓角矩形（`border-radius: 4px–6px`），嚴禁膠囊圓角（Pill/Capsule）與均質單色浮誇背景；以線條邊框、字階與明度區分層級。
  * **呼吸感排版與精準對齊**：清單每一列維持足夠垂直高度（56px），留白均勻。所有檔案容量與百分比均採用等寬字型（Monospace）搭配 `tabular-nums`，徹底杜絕數據抖動。
  * **主題設計理由**：預設採用深色模式（Dark-first），目的在於降低圖片檢視時的周圍光害干擾，提供中性低彩度的看圖環境；同時完整支援 Windows 系統偏好之淺色模式跟隨。

## 2. 資訊架構（IA）與視窗佈局

主視窗預設尺寸為 **860 × 620 px**（支援彈性縮放，設有最小寬高限制：720 × 500 px）。

```text
+-----------------------------------------------------------------+
|  [圖示] TinyPress                           [全域狀態]  [⚙ 設定] |  <- 頂部全域列 (48px)
+-----------------------------------------------------------------+
|                                                                 |
|                                                                 |
|                 主工作區（動態切換：待機空狀態 vs 清單佇列）         |
|                                                                 |
|                                                                 |
+-----------------------------------------------------------------+
|  格式: [ 原格式 ▾ ]   品質: [━●━━━━━] 75%    輸出: [ 同目錄 ▾ ]    |  <- 常駐快捷列 (56px)
+-----------------------------------------------------------------+
```

### 2.1 頂部全域列（Header Bar, 48px）
* **左側**：程式標題與極簡向量圖標。
* **中央狀態（批次處理中動態浮現）**：顯示當前全域進度摘要（如：`正在處理 4/12 張...`），頂部邊界伴隨 2px 高度的極細進度條。
* **右側控制項**：
  * **清空清單**：文字型次要操作，僅在清單有項目時轉為可互動態。
  * **重新處理全部 (R)**：僅在已有已完成項目且快捷列參數變更時浮現。
  * **設定（齒輪圖示）**：4px 微圓角按鈕，點擊後觸發右側抽屜面板展開。

### 2.2 底部常駐快捷列（Quick Bar, 56px）
以 1px 實體分界線（`border-t`）與工作區隔開，收納每次壓縮最頻繁調整的三大參數：
* **輸出格式選擇器**：自訂下拉選單（維持原格式、WebP、AVIF、JPEG、PNG）。
* **品質滑桿（Quality Slider）**：數值顯示與滑動軌道一體化，步進值 1，範圍 1–100。右側附帶極簡狀態文字提示：60 (高壓縮)、75 (平衡推薦)、90 (極致畫質)。
* **儲存位置捷徑**：下拉切換「存至原目錄」或「存至自訂資料夾」。

## 3. 微互動時序與動畫衝突處理規格

### 3.1 待機空狀態（Empty State）
* **視覺呈現**：居中顯示具備呼吸感的內凹虛線框（邊距 24px），圖示採用線條清晰的檔案放置意象。
* **主要文案**：
  * 主標題：「拖放圖片至此，或點擊選取檔案」
  * 副標題：「支援 JPG、PNG、WebP、AVIF ｜ 支援單檔、多選與整個資料夾」
* **滿足感錨點（心理反饋）**：待機區右下角常駐極低對比的次要文字：「本機累計節省空間：1.42 GB」，作為長期使用的效能確認，不加入任何等級或徽章等過度遊戲化元素。

### 3.2 拖放過渡（避免 Hard Cut 與卡頓）
* **懸停回饋**：檔案拖曳進視窗上方瞬間（Drag Over），虛線邊框於 100ms 內過渡為 2px 實線高亮，背景明度微增 2%。
* **佈局切換動態**：放開滑鼠瞬間，空狀態區域於 120ms 內淡出（`opacity: 0`）。清單主容器以 `cubic-bezier(0.16, 1, 0.3, 1)`（Ease-Out Expo）展開。
* **Stagger 上限規格**：僅前 8 列啟用 15ms 階梯差微幅向上淡入（`translateY(6px) → 0`，總時長不超過 120ms），第 9 列起直接渲染就位，避免批次大量檔案時造成主執行緒掉幀。

### 3.3 佇列清單列規格（單列高度 56px）
清單每一列由網格嚴格對齊，欄位自左至右：
```text
+----+--------------------------------+-----------------+---------+----+
|縮圖| 檔名與路徑資訊                  | 體積變化         | 壓縮率  |動作|
+----+--------------------------------+-----------------+---------+----+
|40px| banner_hero_product_v2.png     | 3.4 MB → 1.1 MB | -68%    | [⋯]|
|    | 1920 × 1080                    |                 |         |    |
+----+--------------------------------+-----------------+---------+----+
```
* **微型縮圖（40 × 40 px）**：圓角 4px。
* **檔名與資訊**：
  * 檔名主標：粗體 14px，保留前後文字、中間省略截斷。開放選取（`user-select: text`），便於複製除錯。
  * 解析度副標：12px 弱化次要文字（如 `1920 × 1080`）。
* **體積消長數據**：採用等寬字型，格式為 `原始大小  →  壓縮後大小`。
* **壓縮率標記**：成功時顯示綠色文字標記（如 `-68%`）。
* **列操作項**：懸停於該列時浮現「開啟檔案夾」與「自清單移除」圖示按鈕。

### 3.4 體感節奏與動畫時序表（Perceived Performance Timing）
| 事件階段 | 動態行為規格 | 觸發起點與條件 | 持續時間 | 緩動曲線 (Easing) |
| :--- | :--- | :--- | :--- | :--- |
| **拖放釋放** | 待機框淡出，清單結構展開 | 放開滑鼠即刻觸發 | 120ms | `cubic-bezier(0.16, 1, 0.3, 1)` |
| **清單進場** | 首批 8 列階梯淡入向上微推 | 待機框淡出後依序觸發 | 15ms/列 (上限 120ms) | `cubic-bezier(0.16, 1, 0.3, 1)` |
| **數值過渡** | 等寬數字線性跳動遞減 | 後端發送 `task_completed` 抵達時（純前端插值） | 180ms | `linear` |
| **百分比就位** | 綠色標記向上浮現 | 數值滾動完成後延遲 40ms | 120ms | `cubic-bezier(0.16, 1, 0.3, 1)` |
| **單列完成訊號** | 背景閃爍極淡綠光 | 數值滾動完成當下觸發 | 150ms 快閃後退回原色 | `cubic-bezier(0.4, 0, 0.2, 1)` |

### 3.5 動畫衝突防禦規則（Stagger vs. Flash-Success）
* **屬性分離**：進場動畫僅操作 `transform` 與 `opacity`；完成閃光僅操作 `background-color`，兩者 CSS 屬性互不覆蓋。
* **時序排隊機制**：若壓縮完成事件在該列進場 Stagger 動畫完成前抵達，完成閃光強制延遲至進場動畫結束後（120ms 標記點）才觸發，嚴禁兩者同毫秒混雜觸發導致視覺混亂。

## 4. 控制項行為界限與快捷鍵範疇（Scope）

### 4.1 快捷鍵上下文階層架構（Keyboard Context Stack）
為杜絕彈窗開啟或文字輸入時的按鍵干擾，系統實施嚴格的三層鍵盤事件堆疊：
```text
[Layer 3: 模態覆蓋層 (Modal / Drawer)] ─── 優先權最高
   │ 捕捉: Esc (關閉), Enter (確認主 CTA)
   │ 阻斷: 阻斷所有底層單鍵快捷鍵 (包含 R 鍵)
   ▼
[Layer 2: 焦點鎖定層 (Form Input Focus)]
   │ 判定: activeElement 為 input / textarea / contenteditable
   │ 行為: 停用所有單字母全域快捷鍵，確保文字正常輸入
   ▼
[Layer 1: 主工作區 (Global Workspace)] ─── 預設基礎層
   │ 捕捉: R 鍵 (觸發重新處理全部)
   │ 條件: 僅在「已有完成項目」且「參數已變更」且「非處理中」狀態下生效
```

### 4.2 快捷列「不自動追溯」原則
* **滑桿即時反應**：拖曳滑桿時，右側數值以 50ms 輕度防抖（Debounce） 即時更新文字，同時持久化至本機設定中。
* **影響範圍界限**：
  * 佇列中尚未開始的檔案：立即套用最新參數進行壓縮。
  * 已經壓縮完成的檔案：絕對不自動重複觸發運算。
* **參數變更提示**：若清單內已有已完成項目，頂部全域列右側浮現提示按鈕：`[重新處理全部 (R)]`。

## 6. 完成回饋彈窗（In-App Summary Modal）

批次處理完全結束時，視窗中央以微矩形卡片（6px 圓角、俐落外框）喚起結算摘要。不牽涉系統推播，所有操作皆支援鍵盤無障礙操作。

```text
+--------------------------------------------------------+
|                                                        |
|   批次處理完成                                          |
|   成功處理 24 張圖片，共減少 62% 儲存空間               |
|                                                        |
|   +------------------------------------------------+   |
|   | 原始大小: 48.2 MB    →    壓縮後: 18.3 MB      |   |
|   | 累計節省: 29.9 MB                              |   |
|   +------------------------------------------------+   |
|                                                        |
|   [ 關閉 (Esc) ]                  [ 開啟輸出檔案夾 ↵ ]  |   |
+--------------------------------------------------------+
```
* **關閉（Esc）**：微矩形次要按鈕，灰色邊框。
* **開啟輸出檔案夾（Enter）**：高對比主要按鈕，直接呼叫 Windows 檔案總管並定位該目錄。

## 7. 技術邊界與防線（Technical Guardrails）

* **大圖縮圖非同步防線（防止 WebView2 主執行緒凍結）**：嚴禁前端直接以 HTML `<img src="local_file">` 或 Canvas 解碼 20MB 以上的高解析度原圖。清單載入時，前端縮圖區域先展示格式色塊（PNG / JPG 標籤）；後端 Rust 工作池以最高優先權抽取 80×80 微型縮圖發送。
* **快取沿用原則**：若使用者點擊「重新處理全部 (R)」，縮圖快取維持不變，後端僅重新執行編碼運算，嚴禁重複抽取縮圖。
* **IPC 事件粒度承諾**：後端僅需發送單一的 `task_completed` 完成事件，不發送中間模擬字節串流。前端的 180ms 數字滾動為接收此事件後的本機插值動畫。
* **反向膨脹處置（Negative Compression）**：若重新編碼後的體積大於或等於原檔案，系統自動保留原檔輸出，狀態欄標記灰色「已最佳化（維持原檔）」，不產出負效果檔案。
* **非阻塞式衝突處理（Non-blocking Conflict UX）**：若設為「遇衝突時詢問」，遇到衝突之檔案該列直接顯示黃色警示與三鍵文字操作：`[覆蓋]` / `[更名]` / `[跳過]`；後續無衝突檔案持續在背景平行壓縮，杜絕佇列卡死。
